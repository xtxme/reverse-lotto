All requests below were generated by ordinary authenticated browsing (page loads, tab clicks, and the same-origin GETs the page itself performs). No endpoint paths were guessed, fuzzed, or scanned. No authentication values are reproduced.

## 2. API-01 in detail

### Request

```
GET /member/lottery/yeekee-list-number?id=231&limit=19&offset=0
X-Requested-With: XMLHttpRequest
Accept: application/json, text/javascript, */*; q=0.01
```

Authenticated by the normal session cookie. The `id` is the round/category ID used in the page URL, not the internal `current_period_id`.

### Response

```json
{
  "lists": [
    {
      "username": "Ab***cd",
      "number": "74669",
      "bet_category_id": 229,
      "bet_period_id": "802204",
      "created_at": "2026-11-07 19:01:59"
    }
  ],
  "sum": "9281577"
}
```

Observed details:

- `number` is usually a string when it has a leading zero and an integer otherwise; consumers must handle both.
- `sum` is a string, not a number.
- The endpoint returns **at most 20 rows**, even with `limit=19`. It is a “latest N” view, not the full list.
- Rows are newest-first.
- `bet_period_id` is shared by all rows in a round and differs from the URL `id`.
- `created_at` is a Bangkok-local string without timezone.

### Caching

- `cf-cache-status: DYNAMIC`
- `ETag` present (weak)
- No `Cache-Control` observed on the JSON
- `content-type: application/json; charset=utf-8`

The data is not edge-cached; each poll reflects the current pool.

## 5. Polling, WebSocket, and update mechanism

- **No periodic round polling was observed.** While the page was idle, the only recurring XHR was Cloudflare RUM. The round grid, countdown, and result block are not refreshed by AJAX.
- **Round data is pulled at page load** and then only changes when the page is reloaded.
- **The page reloads itself** when the shoot-window countdown (`close_date + 2 min`) goes negative (`window.location.reload()` in `intervalTimer`). This is the transition that reveals the published result.
- **Pusher** is used for a single agent-notification channel (`notic.agentid.33`, event `numbersets`), not for round or result updates.
- Result publication is therefore pull-based: a client sees a result on the first page load after the server has computed it.

Classification: OBSERVED for the absence of polling, the reload path, and the Pusher channel; INFERRED for the “pull-based result” wording.

## 6. Relationship to round state

| Round state | Page/API behavior |
|---|---|
| Open for betting | `betconfig.is_open = 1`; countdown to `close_date`; list endpoint returns 0 rows until the shooting sub-window opens. |
| Pre-close shooting sub-window (~close−2 min) | list endpoint starts returning rows and a non-zero `sum`; page still shows the betting UI. |
| Closed, shooting | `is_open` display switches off client-side; page shows “ปิดรับการทายผลตัวเลข”; list and sum continue to grow until `close+2 min`. |
| Shoot closed, processing | list/sum final; result block not yet present. |
| Published | server HTML contains `ผลรวมยิงเลข`, `เลขแถวที่ 16`, `ผลรางวัล`, `สามตัวบน`, `สองตัวล่าง`. |
| Archived | older period IDs returned 404 in this session; only current-day rounds were reachable. |

Classification: OBSERVED, except the archived-period behavior which is an observation about this session/account (see limitations).

### 6.1 `is_open` is not a live cut-off indicator

At 19:46:18, round 56 (period 232, `close_date` 19:45:00) still returned `is_open = 1` in its page `betconfig`, as did the next round (period 233). The field therefore appears to describe whether the round/product is enabled, not whether bets are currently accepted. The visible betting cut-off is driven by the server-provided `close_date` and the client countdown; server-side rejection of a late bet was not tested (placing a late bet is outside the research rules).

Classification: OBSERVED for the flag value; UNKNOWN for server-side late-bet enforcement.

## 8. Data relationships exposed

Observed identifiers:

- Round/category ID in the URL (`/member/lottery/yeekee/229`).
- `bet_category_id` in each submission, equal to the URL ID.
- `bet_period_id` internal period ID (e.g. `802204`).
- `current_period_id` in `betconfig` (e.g. `802206` for round 55).
- Display row number (1..N), used for the “16th” rule and the 1/16/100 bonuses.

No database schema, table name, primary key, foreign key, or credential was exposed. The relationships above are application-level identifiers only.

Classification: OBSERVED for the identifiers; UNKNOWN for the underlying schema.
